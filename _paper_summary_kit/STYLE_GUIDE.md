# Structured Summary Style Guide

この文書は、QAmatomer の tree UI をどう活かせるかについてのメモです。  
JSON の形式や必須フィールドは `TOOL_MANUAL.md` を見てください。

## tree UI の性質

- 子 node を開いている間も、親 node は開かれたまま残る
- そのため、親 node が文脈や整理の軸を与えていると読みやすい
- 一方で、階層を深くするほど右に移動して読むことになる
- そのため、中身の薄い中間 node を挟むと見づらくなることがある

## この構造で表せること

QAmatomer では、たとえば次のような分け方ができます。

- 全体の見通しと個別の詳細
- 比較表と各項目の説明
- 概略と具体例
- 複数の論点の並列
- 流れや依存関係

どの分け方が合うかは source によります。固定の分け方は前提にしません。

## node の考え方

- node は、1つの論点、定義群、比較テーマ、手順、例などのまとまりとして使える
- 親 node が子を束ねる文脈になっているなら、その段は意味を持ちやすい
- 親 node の中身が小さいなら、無理に1段挟まず上に並べた方が見やすいことがある

## section の考え方

- 同じ node の中で続けて読む方が自然な内容は、section に分けて書ける
- たとえば `概観`, `主張`, `理由`, `例`, `比較`, `注意`, `帰結` のような section を置ける

## guide

- `guide` は、読み順、依存関係、索引、見取り図などをまとめる場所として使える
